# Controls artwork

`ps1-controller.png` is the transparent PNG edit of the controller image supplied
by the user on 2026-09-21. It was prepared with the built-in image generation/edit
tool (background extraction), not the CLI. The white background and white
interior areas are transparent. The image is a digital PS1 pad without analog
sticks; L3/R3 remain available in the binding table only.

Final prompt:

> Edit the supplied image: remove white to transparent. Preserve the controller drawing exactly. Output a clean transparent PNG, 659x477 if possible. Flat cyan outline #00B4D0 with smooth clean antialiased edges. All areas that were white, including enclosed interior regions, must be completely transparent. Keep the exact geometry and buttons of the provided original PlayStation digital controller, no analog sticks. Remove only the tiny stray cyan mark at the extreme top boundary. No noise, no speckles, no rough edges, no fill patches, no double outlines, no glow, no shadow, no checkerboard, no text, no new symbols. This is clean vector-like UI line art, not a textured drawing.

The tool produced a 1474 × 1067 RGBA asset. The PNG bytes are embedded unchanged
in `ps1_controller_png.h`, generated by:

```sh
python3 tools/pc/embed_controls_art.py
```

`controls_art.c` decodes it with libpng once, caches a scaled copy and alpha-blends
it onto `MenuCanvas`. This works identically in SDL and X11 and does not require a
particular working directory. Both the host tests and the native 32-bit build
need libpng development headers/libraries for their target architecture.
Button hit regions in `controls_window.c` follow the artwork; live highlights and
small PS1 symbols are drawn separately, without modifying the saved PNG.
